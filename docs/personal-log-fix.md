# 올림픽 개인 로그 누락 수정 (2026-10-10)

운영에서는 올림픽 날짜 조회가 정상 완료됐지만, 보관된 올림픽 원문 로그에 대응하는 구조화 로그가 없었다. 개인정보 없는 집계로 원문 로그 존재와 구조화 로그 누락을 확인했다.

재현: 다른 제공자 조회 잠금을 유지한 채 한 제공자만 조회하면, checkAllVenues가 미선택 제공자에도 잠금 확인을 수행해 DUPLICATE_SKIPPED를 현재 조회의 오류에 추가했다. 요약에는 요청한 제공자만 표시되는데 저장 정규화는 모든 오류 제공자 이름이 요약에 있어야 한다고 판단해 상세 로그 전체를 버렸다. 개인 로그는 원문 공개를 피하기 위해 구조화 로그만 표시하므로 결과가 비어 보였다.

수정:
- 요청한 시설의 제공자만 safeProviderCheck에 전달한다. 진단용 전체 조회는 유지한다.
- 영속 로그 ID가 정확히 일치하면 그 연결을 신뢰한다. 과거 ID 없는 로그에만 텍스트 호환 검사를 적용한다.
- 개인 응답에서는 기존처럼 본인 알림 대상·시설·날짜로 필터링한다. 다른 제공자의 오류나 공용 원문을 전달하지 않는다.

검증:
- 미선택 하남 제공자의 잠금을 유지한 상태에서 강동만 조회해 중복 오류가 섞이지 않는지 확인.
- 올림픽 성공과 다른 제공자 중복 오류가 함께 있는 레코드를 저장·재로드·API 조회해 올림픽 기록이 유지되고 다른 오류가 제외되는지 확인.
- 이미 삭제된 상세 기록은 복구하지 않는다. 수정 후 다음 조회부터 새 정상 로그가 보관된다.
