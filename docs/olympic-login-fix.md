# 올림픽 로그인 경로 수정 (2026-10-09)

## 운영 로그로 확인한 직접 원인

Railway tennis 서비스의 ea33f6c 배포에서 KST 13:50 및 13:55 조회는 각각 약 33.8초, 33.2초 뒤 실패했다. 전체 provider 240초 초과가 아니라 `locator.fill: Timeout 10000ms exceeded`였으며, `#login_id, input[name='login_id']` 입력칸을 기다리고 있었다.

현재 공식 [테니스 로그인 페이지](https://www.ksponco.or.kr/online/tennis/login.do)의 실제 필드는 `#user_id`, `#user_pwd`이고, 제출 버튼은 `fn_login1()`을 실행한다. 비로그인 상태에서 예약신청 URL에 접근하면 홈으로 이동하므로 예약 URL에서 예전 로그인 필드를 찾는 코드가 실패한다. 날짜를 하나로 줄여도 로그인 전 단계의 이 오류는 발생한다.

비로그인 홈에도 마이페이지·신청내역 메뉴가 있어서, 기존 로그인 상태 검사는 공개 메뉴를 로그인 성공으로 잘못 판단했다. 그 뒤 예약페이지의 달력을 기다리며 약 17초를 낭비한 뒤 잘못된 로그인 경로로 진행했다.

## 수정

- 테니스 전용 login.do를 열고 실제 user_id/user_pwd 필드와 로그인 버튼을 선택한다. 기존 login_id/login_pwd 필드는 호환 선택자로 유지한다.
- 로그인 성공 판단은 로그아웃 표시를 요구한다. 공개 마이페이지·신청내역 메뉴만으로 로그인됐다고 판단하지 않는다.
- 로그인페이지 접근, 입력폼 확인, 로그인 완료 확인을 별도 단계로 기록한다.
- 로그인 입력폼이 없으면 LOGIN_FORM_CHANGED를 반환해 일반 응답 지연과 구분한다.
- 로그인 전후 networkidle 대기를 제거한다. 실제 입력폼 준비·로그인 상태·예약 달력 검증을 사용한다.
- 인증된 예약 URL을 직접 열고 달력이 준비됐는지 확인한다. 홈/로그인 화면으로 돌아가거나 달력이 준비되지 않는 오류를 숨기지 않는다.
- 중복 세션 감지와 자동 접속 탈취 거절 동작을 유지한다.

## 검증

전체 작업 폴더: 30개 테스트 파일 / 297개 테스트 통과.
실제 Chromium으로 공식 로그인 페이지에 계정 입력 없이 접속해 아이디·비밀번호·제출 버튼이 각각 1개이며 보이는지 확인했다. 비로그인 홈은 로그인 상태가 아닌 것으로 판별했다.
로그인 경로, 공개 메뉴 오인, 입력폼 변경, 인증 리다이렉트, 페이지 이동 실패, 인증 완료 미확인 회귀 테스트를 추가했다. 운영과의 중복 로그인을 피하기 위해 로컬에서 실제 계정 로그인은 수행하지 않았다.
운영 적용 후 정상 조회 여부는 새 배포의 스케줄러 로그로 확인한다.

커밋 대상 스냅샷: 27개 테스트 파일 / 265개 테스트 통과.
