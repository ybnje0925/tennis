# 송파 화면 읽기 오류 수정 (2026-09-30)

## 확인한 원인
- 9월 현재 날짜의 실제 HTML은 시간대별 '접수불가'를 반환했다. 기존 파서는 예약가능/예약완료/예약불가만 인식해 모든 회차를 버렸고 PARSE_FAILED가 발생했다.
- 기존 브라우저 경로는 watch의 dates를 받아도 현재 달만 읽었다. 10월 조건을 9월 화면에서 찾는 문제가 있었다.
- HTTP 경로의 공통 구형 파서는 (예약 수/정원)의 분자를 잔여 수로 사용했다. 브라우저와 HTTP 계산을 통일했다.

## 실제 응답 확인
- 비로그인 오륜 목록 GET 200은 로그인 요청 스크립트였다. 송파는 로그인 필요.
- 기존 송파 설정 계정으로 정상 로그인 후, s04(오륜), s06(성내천), s05(송파), s03(오금)의 목록에 ?sch_sym=2026-10을 지정해 4개 모두 200 및 헤더 '2026 . 10'을 확인했다.
- 실제 이전/다음 달 링크도 sch_sym 파라미터를 사용한다.
- calendar1_yearmonth 헤더와 calendar1_table의 h6 날짜·li 회차를 파싱한다.
- 9월 23일은 날짜 전체 예약불가, 25~26일은 추석 문구, 30일은 시간대별 접수불가였다.
- 10월 공개 현황의 예약가능 (2/3), (1/2) 등은 정원에서 예약 수를 빼 잔여 수를 계산한다.
- 로그인·예약 수치 외의 개인 데이터는 fixture에 저장하지 않았다. 예약/결제 요청과 테스트 텔레그램 발송은 하지 않았다.
- 로컬 Node 진단 시 시스템 CA를 정상 사용했다. 인증서 검증을 끄지 않았다. 운영 환경 설정은 변경하지 않았다.

## 수정
- src/providers/songpaCalendar.js: HTTP/브라우저 공통 파서. 접수불가를 unavailable로 분류하고 예약 수/정원 계산을 통일한다.
- src/providers/songpaProvider.js: 조건에 지정된 달마다 목록을 한 번 조회, 응답 달·대상 날짜 셀 검증 및 결과 날짜 필터/정렬. 로그인 리다이렉트를 화면 읽기 실패와 구분한다.
- src/legacyHttpParser.js: 송파만 전용 공통 파서로 전달. 강동 계산 유지.
- 휴일/행사처럼 시간대가 없는 셀은 가용 상태를 만들어내지 않는다. 날짜 셀 확인 여부와 슬롯 수를 구분해 빈 목록을 무조건 파싱 실패로 판단하지 않는다.
- 알려지지 않은 시간대 상태나 깨진 달력은 계속 오류로 반환해 이전 알림 상태를 보존한다.
- tests/songpaCalendar.test.js 및 실제 응답 fixture 5개 추가, tests/legacyHttpParser.test.js의 잘못된 잔여 수 기대값 수정.
