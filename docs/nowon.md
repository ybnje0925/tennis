# 노원 연동 상태 및 운영 안내

2026-10-02 기준: 시설·설정 저장·공통 스케줄러·인증 모듈·조건 매칭·알림 형식은 추가했지만,
**인증 후 상세 시간표의 실제 요청과 HTML 파서는 미구현/미검증입니다. 노원 알림은 아직 운영할 수 없습니다.**
`NOWON_TIMETABLE_VERIFIED=false` 및 `verifiedDayLoader` 중단으로 허위 빈자리 알림을 방지합니다.
계정 설정 이후에도 이 상태는 유지됩니다. 다른 시설 조회는 계속 동작합니다.

## 공식 사이트에서 확인한 구조

- [테니스장 목록](https://reservation.nowonsc.kr/sports/tennis_list)의 대관신청 링크:
  `/sports/courtReserve_date?cate1=1&cate2=시설ID`.
- 시설ID/코트수: 마들 `16`/9, 초안산 `17`/4, 불암산 `15`/3, 수락산 `117`/3.
  수락산의 이용안내 ID `21`을 예약 ID로 사용하지 않습니다.
- 목록에 안내된 운영시간은 네 시설 모두 06:00~22:00.
  휴장/레슨 등 실제 날짜별 시간표와 개별 코트 이름·번호는 인증 후 다시 검증해야 합니다.
  설정 화면의 1~N 코트 선택은 목록의 코트수에 기반합니다. 인증된 시간표와의 매핑은 미검증입니다.
- 로그인 화면 `/member/login`, 실제 공개 스크립트 `/js/cust/login.js?v=20211208`:
  POST `/member/loginAction`, form-urlencoded `memberId`, `memberPassword`.
  공개 폼에서 CSRF hidden input은 발견되지 않았습니다. 모듈은 폼에 추가되는 hidden 필드를 전달합니다.
- 실제 공개 로그인 응답에서 JSESSIONID 쿠키 발급을 확인했습니다. 쿠키를 보존하고 redirect도 동일 origin 안에서만 따라갑니다. 세션 쿠키는 서버 메모리에만 보관합니다.
- login.js의 결과코드: `0` 성공, `12` 자격증명 불일치, `14` 계정 차단,
  `15` 누적 오류로 차단, `11` 비밀번호 변경, `13` 휴면 해제 확인.
  구현은 코드 `0` 외에 로그인 이후 페이지의 실제 로그아웃 링크도 요구합니다.
  성공 응답의 실제 JSON 자료형과 로그아웃 링크는 계정이 없어 실검증하지 못했습니다.
- 비로그인 대관신청/현황 접근은 `/member/login;jsessionid=…`로 이동하고 HTTP 200 로그인 폼을 반환합니다.
  HTML의 실제 `memberPassword` input 및 로그인 URL로 구분합니다. raw redirect URL은 로그에 남기지 않습니다.
- [예약 상태 표시 공지](https://reservation.nowonsc.kr/notice/view?seq=521): 달력 표시를 빈자리 증거로 사용하지 않습니다.
- 목록의 관내 우선예약 안내에 따라 계정 자격이 예약 오픈 시점에 영향을 줍니다.
  관내·관외 계정의 상세 응답 차이는 미검증입니다. 알림에는 본인 계정 자격 확인을 안내합니다.

## 빈자리 상태 규칙과 미검증 부분

사용자가 확인한 파란 시간=가능, 빨간 글자+취소선=불가 규칙은 내부 정규화 데이터 매칭에 반영했습니다.
체크박스·달력 문구는 매칭에 사용하지 않습니다. 파란 표시와 disabled/명시적 불가가 충돌하거나
상태를 모르면 날짜 조회 실패로 처리하고 이전 이력을 보존합니다.
같은 시설·날짜·코트의 1시간 두 개가 붙어 있고 선택 시간대에 모두 포함되어야 연속 2시간으로 인정합니다.

`nowonSlots.js`의 입력은 내부 정규화 계약입니다. **실제 사이트 HTML을 파싱하는 코드라는 뜻이 아닙니다.**
`nowon.test.js`의 blue/red-strike 자료는 합성 mock이며 실제 상태 클래스·색상 코드·데이터 필드를 가정하지 않습니다.
실제 상세 시간표 요청 URL/메서드/날짜·월 파라미터/상태값/선택자는 아직 확인하지 못했습니다.
확인되지 않은 API나 선택자를 추측해서 호출하는 코드는 없습니다.

완성에 필요한 후속 검증:
1. 운영자가 서버 변수 설정 후 아래 진단으로 정상 인증을 확인합니다.
2. 인증 후 HTML과 해당 페이지가 참조하는 실제 스크립트, 정상적인 날짜 선택 조회를 조사합니다.
3. 날짜별 한 응답에서 실제 코트·시간·표시 스타일과 연결된 상태를 추출하는 HTTP loader를 구현합니다.
4. 개인정보/토큰을 제거한 실제 fixture로 파란 시간·빨간 취소선·모순·빈 달력·시설별 코트를 검증합니다.
5. 모든 검증 후에만 `NOWON_TIMETABLE_VERIFIED`와 production loader를 활성화합니다.
   flag만 true로 바꾸면 loader가 계속 중단하므로 실빈자리 알림이 시작되지 않습니다.

## Railway 설정

[Variables 안내](https://docs.railway.com/variables)에 따라 서비스 Variables에 아래 두 변수를 설정하고
변경사항을 배포해 적용합니다. 값을 채팅·Git·프런트엔드에 넣지 않습니다.

```dotenv
NOWON_USERNAME=
NOWON_PASSWORD=
```

[Volume 안내](https://docs.railway.com/volumes)에 따라 기존 상태 저장용 volume과 DATA_DIR을 유지합니다.
인증 중단 기록은 DATA_DIR/nowon-auth-stop.json에 저장됩니다. 계정정보/쿠키는 저장되지 않습니다.
DATA_DIR이 비어 있고 Railway volume이 있으면 기존 설정대로 volume 아래 data 디렉터리를 사용합니다.
영속 volume이 없으면 재배포 시 중단 기록이 유실될 수 있습니다. 기존 설정을 보존하려면 data 경로를 바꾸지 마세요.
현재 앱은 단일 프로세스/단일 replica의 공유 세션을 전제로 합니다.

## 로그인·조회 확인 및 인증 중단 재개

운영 서비스와 같은 환경변수 및 **같은 volume/DATA_DIR**을 사용하는 컨테이너 셸에서:

```sh
npm run diagnose:nowon
```

누락 시 `로그인 설정 필요`, 성공 시 `로그인 결과 0 및 로그아웃 링크 확인`을 출력합니다.
그 뒤 네 시설의 인증 페이지와 참조 스크립트 경로만 확인합니다. **날짜별 실제 빈자리 검증 명령은 아직 아닙니다.**
아이디·비밀번호·쿠키·토큰·원문 응답·세션 URL은 출력하지 않습니다. 예약이나 텔레그램 발송도 하지 않습니다.

자격증명 오류/차단/추가 인증/로그인 POST 결과 불확실 시 자동 로그인을 중단합니다.
공식 사이트에서 계정 문제를 해결하고 서버 변수를 올바르게 설정한 뒤 운영자가 한 번만 실행합니다:

```sh
npm run diagnose:nowon -- --resume-auth
```

실행 중인 서비스는 메모리에도 중단 상태를 보관하므로, 진단 성공 후 서비스 프로세스를 재시작합니다.
환경변수 변경이나 재시작만으로 영속 중단 기록을 자동 해제하지 않습니다.
동시 로그인은 하나의 Promise로 공유하고, 세션 만료 시 한 번 재로그인한 뒤 해당 GET만 한 번 다시 실행합니다.
GET 네트워크 오류는 최대 한 번 재시도(750ms backoff), 인증 POST는 자동 재전송하지 않습니다.
POST가 서버에 도달했는지 모르는 오류도 운영자 확인 전에는 재전송하지 않습니다.

## 자원·공통 조회·알림 정책

- 기존 5분 스케줄러와 야간 절전 정책을 재사용합니다. 사용자별 타이머/브라우저는 없습니다.
- 활성 조건의 시설/날짜를 deduplicate하고, 날짜 응답의 모든 코트를 사용자별로 매칭합니다.
- provider 조회 잠금은 checker의 기존 구조를 재사용합니다. 날짜별 pending Promise는 공유하고 완료 시 제거합니다.
- 같은 주기 안에서는 공유하지만 다음 주기의 fresh 조회를 가로막는 장기 cache는 만들지 않았습니다.
- 시설의 날짜 중 하나라도 조회 실패하면 그 시설을 성공한 빈 결과로 반환하지 않습니다.
- 조회 실패는 예약 마감으로 저장하지 않고, 복구 시 유지된 빈자리를 신규 빈자리로 오인하지 않습니다.
- 기존 사용자별 Telegram 발송·watch별 중복 방지·마감 후 재알림 정책을 재사용합니다.
- 대시보드에 노원 마지막 시도·성공, 인증/조회 오류와 이전 성공 결과의 오래됨을 표시합니다.

현재 production gate에서는 upstream 조회 **0회/주기**입니다. 계정 진단은 로그인 GET 1회 + POST 1회 +
확인 GET 1회 + 시설 페이지 GET 최대 4회(+redirect/한정된 GET 재시도)이며 알림을 보내지 않습니다.
상세 loader 완성 후 설계상 날짜별 요청은 고유 시설/날짜 쌍당 1회입니다.
실제 달력·날짜 요청 수는 인증 후 요청 구조를 확인해야 산정할 수 있습니다.
production 브라우저 사용은 0개입니다. 개발 검증에서만 임시 Playwright를 사용하고 종료했습니다.

## 검증 기록

- 실제 공개 로그인 폼 fixture: 계정·토큰 값 없음. 성공/실패 JSON은 공개 login.js의 코드 기반 mock.
- 공유 로그인, 인증 오류 latch, HTTP 200 로그인, expiry 단일 재인증, 추가 인증 중단 테스트.
- 합성 상세 상태에서 빨간 취소선, 파란 시간, 체크박스 무관성, 달력 오인 방지, 모순/미상 실패 테스트.
- 같은 코트 연속시간, 시설/날짜/코트 매핑, 공유 조회, 다음 주기 갱신, 알림 중복/오류복구 테스트.
- HTTP API 테스트로 코트/이용시간 PC·모바일 동기화 및 잘못된 조건 거부 확인.
- 실제 브라우저의 비로그인 공식 시설 링크→로그인 이동 확인.
- mock API 기반 1280px/390px UI 흐름: 실제 payload의 3코트/연속2시간, JS 오류/가로 overflow 없음.
- 실제 운영자 로그인/인증된 시간표 파싱/관내·관외 응답 비교/실사용자 텔레그램: **실시하지 않음**.

최종 회귀 결과: 28개 테스트 파일, 275개 테스트 통과. 실제 사용자 알림 발송 없음.
