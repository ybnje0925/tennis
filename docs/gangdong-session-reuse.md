# 강동 HTTP 세션 재사용

강동 자동조회는 서버 프로세스의 CookieSession을 조회 주기 사이에 재사용한다.
최초 조회 시 로그인 페이지 GET과 인증 POST를 수행하고, 이후 필요한 시설·월의 달력만 요청한다.
계정 정보와 쿠키는 파일이나 로그에 저장하지 않는다. 서버 재시작 시에는 다시 로그인한다.

달력의 로그인 리다이렉트, 401, 실제 비밀번호 입력 폼 또는 달력 없는 인증 안내 응답을
인증 만료로 판단한다. 한 달력 요청에서 재로그인과 재조회는 한 번만 허용한다.
동시 호출은 로그인 Promise와 인증 세대 번호를 공유해 중복 재로그인을 방지한다.
로그인 이후 인증 실패가 계속되면 해당 조회 주기의 남은 달력은 추가 요청 없이 오류로 보고한다.
403·429·5xx, 통신 실패, 파싱 실패는 재로그인을 유발하지 않는다.
정상 달력의 '로그인 후' 안내문은 인증 실패로 처리하지 않는다.

중복 시설과 같은 시설의 같은 월 요청은 합친다. 달력 실패 시 다른 달력의 성공 결과를 보존한다.
강동 HTTP 실패 후 Playwright 자동 fallback은 제거했다. 추가 로그인과 전체 시설 재조회를
방지하기 위한 동작 변경이며, LEGACY_HTTP_FALLBACK은 이제 강동 HTTP 경로에 적용되지 않는다.
브라우저 경로가 명시적으로 필요하면 LEGACY_HTTP_ENABLED=false를 사용한다.
다른 제공자의 fallback 설정과 조회 주기는 바꾸지 않았다.

5분 주기, 강일·명일 각각 한 달, 단일 프로세스, 수동 조회·오류가 없는 경우:

| 요청 | 변경 전 시간당 | 최초 로그인 포함 시간 | 세션 유효 시간 |
|---|---:|---:|---:|
| 로그인 페이지 GET | 12 | 1 | 0 |
| 인증 POST | 12 | 1 | 0 |
| 예약 달력 GET | 24 | 24 | 24 |
| 합계 | 48 | 26 | 24 |

실제 세션 수명은 확인하지 않았다. 만료 시 실패한 달력 요청 및 재인증·재조회가 추가된다.
세션과 기존 조회 잠금은 프로세스별이므로 여러 replica 사이에서는 공유되지 않는다.
자동조회 중단 상태를 변경하거나 외부 예약사이트 실요청을 실행하지 않고 모의 응답으로 검증한다.
